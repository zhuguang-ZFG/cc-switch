# 5.1 配置文件说明

## CC Switch 数据存储

### 存储目录

默认位置：`~/.cc-switch/`

可在设置中自定义位置（用于云同步）。

### 目录结构

```
~/.cc-switch/
├── cc-switch.db      # SQLite 数据库（SSOT）
├── settings.json     # 设备级设置
├── skills/           # 技能 SSOT 目录
├── skill-backups/    # 技能备份（卸载时创建）
└── backups/          # 数据库备份
```

### 数据库内容

`cc-switch.db` 是 SQLite 数据库，存储：

| 表 | 内容 |
|-----|------|
| providers | 供应商配置 |
| provider_endpoints | 供应商端点候选列表 |
| mcp_servers | MCP 服务器配置 |
| prompts | 提示词预设 |
| skills | 技能安装状态 |
| skill_repos | 技能仓库配置 |
| proxy_config | 代理配置 |
| proxy_request_logs | 代理请求日志 |
| provider_health | 供应商健康状态 |
| model_pricing | 模型定价 |
| settings | 应用设置 |

### 设备设置

`settings.json` 存储设备级设置：

```json
{
  "language": "zh",
  "theme": "system",
  "windowBehavior": "minimize",
  "autoStart": false,
  "claudeConfigDir": null,
  "codexConfigDir": null,
  "grokConfigDir": null,
  "opencodeConfigDir": null,
  "openclawConfigDir": null,
  "kimiConfigDir": null,
  "reasonixConfigDir": null,
  "piConfigDir": null
}
```

这些设置不会跨设备同步。

### 自动备份

`backups/` 目录存储自动备份：

- 每次导入配置前自动创建
- 保留最近 10 个备份
- 文件名包含时间戳

## Claude Code 配置

### 配置目录

默认：`~/.claude/`

### 主要文件

```
~/.claude/
├── settings.json     # 主配置文件
├── CLAUDE.md         # 系统提示词
└── skills/           # 技能目录
    └── ...
```

### settings.json

```json
{
  "env": {
    "ANTHROPIC_API_KEY": "sk-xxx",
    "ANTHROPIC_BASE_URL": "https://api.anthropic.com"
  },
  "permissions": {
    "allow_file_access": true
  }
}
```

| 字段 | 说明 |
|------|------|
| `env.ANTHROPIC_API_KEY` | API 密钥 |
| `env.ANTHROPIC_BASE_URL` | API 端点（可选） |
| `env.ANTHROPIC_AUTH_TOKEN` | 替代认证方式 |

### MCP 配置

MCP 服务器配置在 `~/.claude.json`：

```json
{
  "mcpServers": {
    "mcp-fetch": {
      "command": "uvx",
      "args": ["mcp-server-fetch"]
    }
  }
}
```

## Grok Build 配置

### 配置目录

默认：`~/.grok/`

### 主要文件

```
~/.grok/
├── config.toml       # 主配置 + MCP
├── AGENTS.md         # 系统提示词
├── skills/           # 技能目录
└── sessions/         # 会话目录
```

### config.toml

Grok Build 使用 TOML 配置，切换供应商时整文件写入：

```toml
# 基础配置
base_url = "https://api.x.ai/v1"
api_key = "your-api-key"
default_model = "grok-code-fast-1"

[models.grok-code-fast-1]

# MCP 服务器
[mcp_servers.mcp-fetch]
command = "uvx"
args = ["mcp-server-fetch"]
```

| 字段 | 说明 |
|------|------|
| `base_url` | API 端点地址 |
| `api_key` | API 密钥 |
| `default_model` | 默认使用的模型 |
| `models` | 可用模型列表 |
| `mcp_servers` | MCP 服务器配置 |

## Kimi Code 配置

### 配置目录

默认：`~/.kimi-code/`

可在设置中修改（对应设置项 `kimi_config_dir`），也可通过环境变量 `KIMI_CODE_HOME` 覆盖。

### 主要文件

```
~/.kimi-code/
├── config.toml       # 主配置（供应商与模型）
├── mcp.json          # MCP 服务器配置
├── credentials/      # OAuth 凭据（*.json）
├── AGENTS.md         # 系统提示词
├── skills/           # 技能目录
└── sessions/         # 会话目录（含 session_index.jsonl 索引）
```

### config.toml

Kimi Code 使用 TOML 配置。CC Switch 以增量方式写入 `[providers.<name>]` 与 `[models.<alias>]` 小节，并设置顶层 `default_model`：

```toml
default_model = "my-provider/my-model"

[providers.my-provider]
base_url = "https://api.example.com/v1"
api_key = "your-api-key"

[models.my-model]
provider = "my-provider"
model = "my-model"
```

### mcp.json

MCP 服务器配置在独立的 `mcp.json` 文件中：

```json
{
  "mcpServers": {
    "mcp-fetch": {
      "command": "uvx",
      "args": ["mcp-server-fetch"]
    }
  }
}
```

## Reasonix 配置

### 配置目录

默认：POSIX 为 `~/.reasonix/`，Windows 为 `%APPDATA%\reasonix`。

可在设置中修改，也可通过环境变量 `REASONIX_HOME` 覆盖；会话状态根目录可通过 `REASONIX_STATE_HOME` 覆盖。

### 主要文件

```
~/.reasonix/
├── config.toml       # 主配置（供应商与 MCP 插件）
├── .env              # API keys（由 api_key_env 引用）
├── REASONIX.md       # 系统提示词（优先；否则使用 AGENTS.md）
├── skills/           # 技能目录
└── sessions/         # 会话目录（另见 projects/*/sessions）
```

### config.toml

Reasonix 使用 TOML 配置。CC Switch 以增量方式追加 `[[providers]]` 表数组条目并设置顶层 `default_model`；MCP 服务器以 `[[plugins]]` 表数组形式写入同一文件：

```toml
default_model = "my-provider/my-model"

[[providers]]
name = "my-provider"
base_url = "https://api.example.com/v1"
api_key_env = "CC_SWITCH_MY_PROVIDER_API_KEY"

[[plugins]]
name = "mcp-fetch"
command = "uvx"
args = ["mcp-server-fetch"]
```

### .env

API Key 写入 `.env`，变量名由 CC Switch 生成并在 `config.toml` 中通过 `api_key_env` 引用：

```bash
CC_SWITCH_MY_PROVIDER_API_KEY=your-api-key
```

> ⚠️ **注意**：Reasonix 不支持「通用配置」片段功能。

## OpenClaw 配置

### 配置目录

默认：`~/.openclaw/`

### 主要文件

```
~/.openclaw/
├── openclaw.json     # 主配置文件（JSON5 格式）
└── skills/           # 技能目录
    └── ...
```

### openclaw.json

OpenClaw 使用 JSON5 格式配置文件，主要包含以下部分：

```json5
{
  // 模型供应商配置
  models: {
    mode: "merge",
    providers: {
      "custom-provider": {
        baseUrl: "https://api.example.com/v1",
        apiKey: "your-api-key",
        api: "openai-completions",
        models: [{ id: "model-id", name: "Model Name" }]
      }
    }
  },
  // 环境变量
  env: {
    ANTHROPIC_API_KEY: "sk-..."
  },
  // Agent 默认配置
  agents: {
    defaults: {
      model: {
        primary: "provider/model"
      },
      workspace: "~/.openclaw/workspace"
    }
  },
  // 工具配置
  tools: {}
}
```

| 字段 | 说明 |
|------|------|
| `models.providers` | 供应商配置（映射为 CC Switch 的"供应商"） |
| `env` | 环境变量配置 |
| `agents.defaults` | Agent 默认模型设置 |
| `tools` | 工具配置 |
| `agents.defaults.workspace` | 工作区目录路径 |

## Pi 配置

### 配置目录

默认：`~/.pi/agent/`

可在设置中修改（对应设置项 `piConfigDir`），也可通过环境变量 `PI_AGENT_HOME` 覆盖。

### 关键文件

```
~/.pi/agent/
├── models.json       # 供应商与模型（camelCase 的 baseUrl / apiKey）
├── auth.json         # 各供应商的 API 凭据
├── settings.json     # 应用级设置（默认供应商/模型）
├── AGENTS.md         # 系统提示词
├── skills/           # 技能目录
└── sessions/         # 会话存储
```

### models.json

Pi 使用 JSON 配置。切换供应商时，CC Switch 会在 `providers.<id>` 下增量写入供应商条目及其模型列表：

```json
{
  "providers": {
    "my-provider": {
      "baseUrl": "https://api.example.com/v1",
      "apiKey": "sk-xxx",
      "models": [{ "id": "my-model", "name": "my-model" }]
    }
  }
}
```

| 字段 | 说明 |
|------|------|
| `providers.<id>.baseUrl` | API 端点地址 |
| `providers.<id>.apiKey` | API 密钥（同时写入 `auth.json`） |
| `providers.<id>.models` | 可用模型列表 |

## 配置优先级

CC Switch 修改配置时的优先级：

1. **CC Switch 数据库** - 单一事实源 (SSOT)
2. **Live 配置文件** - 切换供应商时写入
3. **回填机制** - 编辑当前供应商时从 Live 文件读取

## 手动编辑配置

### 可以手动编辑

- CLI 工具的配置文件（会被 CC Switch 回填）
- CC Switch 的 `settings.json`

### 不建议手动编辑

- `cc-switch.db` 数据库文件
- 备份文件

### 编辑后同步

如果手动编辑了 CLI 工具的配置：

1. 打开 CC Switch
2. 编辑对应的供应商
3. 会看到手动修改的内容已回填
4. 保存以同步到数据库

## 配置迁移

### 从旧版本迁移

CC Switch v3.7.0 从 JSON 文件迁移到 SQLite：

- 首次启动自动迁移
- 迁移成功后显示提示
- 旧配置文件保留作为备份

### 跨设备迁移

1. 在源设备导出配置
2. 在目标设备导入配置
3. 或使用云同步功能

## 配置备份建议

### 定期备份

建议定期导出配置：

1. 设置 → 高级 → 数据管理
2. 点击「导出」
3. 保存到安全位置

### 备份内容

导出文件包含：

- 所有供应商配置
- MCP 服务器配置
- Prompts 预设
- 应用设置

### 不包含的内容

- 用量日志（数据量大）
- 设备级设置（不适合跨设备）
